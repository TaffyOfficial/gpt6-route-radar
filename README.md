# Route Radar · 多模型渠道雷达

[在线使用](https://taffyofficial.github.io/gpt6-route-radar/) · [源码](https://github.com/TaffyOfficial/gpt6-route-radar) · [采集与部署状态](https://github.com/TaffyOfficial/gpt6-route-radar/actions/workflows/refresh-pages.yml)

MIT 开源。公开行情数据来自 CodeGo，数据权利归原提供方。

支持按模型选择渠道，默认 GPT6 Astra；可切换 Opus 5、Sonnet 5、Fable 5.1、GPT5.6 Sol。GPT 系列限定 Codex Pro，Claude 系列覆盖支持所选模型的全部公开来源。公开倍率 **≥ 0.20** 的渠道进入榜单。公开 API 真数据，无需登录或 Key。

默认显示所有符合基础筛选的渠道，不设条数上限；支持每页 20 / 50 / 100 条、全部展示及跳页。全部渠道按综合分排序：通过推荐门槛为 50–100 分，未通过降至 0–49 分，保留在主榜并列明原因。每条渠道直接列出完整支持模型，点击渠道名可查看各模型成功率、缓存与请求数。

搜索支持渠道编号（精确匹配）、渠道名和分组 ID；搜索结果保留完整榜单名次。低于最低倍率或被拉黑的渠道会说明未上榜原因，不参与评分或导出。153、80 等 0.20× 渠道现在进入主榜，是否推荐仍取决于成功率等门槛。快照额外保留低倍率渠道供查询，不改变主榜范围。历史实扣只取 `avg_consumer_amount_by_model[所选模型 ID]`，缺失时显示 `—`，不使用其他模型或渠道汇总代替。

## 模型选择

页面左侧「选择模型」切换榜单，成功率、样本、缓存、验证结果和历史实扣均按该模型独立读取。切换保留评分条件和搜索词，重置页码与渠道详情；URL 的 `model` 参数可分享并在刷新后保留选择。黑名单仍按渠道生效，跨模型共用。

| 显示名称 | API 模型 ID | 来源范围 |
| --- | --- | --- |
| GPT6 Astra | `gpt-6-astra` | Codex Pro |
| Opus 5 | `claude-opus-5` | 全部公开来源 |
| Sonnet 5 | `claude-sonnet-5` | 全部公开来源 |
| Fable 5.1 | `claude-fable-5-1` | 全部公开来源 |
| GPT5.6 Sol | `gpt-5.6-sol` | Codex Pro |

Fable 5.1 使用市场实际收录的 `claude-fable-5-1`，不与其他别名混算。采集和 Pages 构建一次生成全部模型快照；任何分页失败都保留上一份完整发布。导出文件名和 `model` 对应当前选择，渠道条目包含实际来源。旧单模型快照切换到新增模型时提示等待更新，不借用 GPT6 数据。

## 黑名单

渠道旁或详情中点击「拉黑」，即从榜单、推荐和新导出的调度建议中排除。支持撤销最近一次拉黑；「黑名单」页支持单条恢复和全部恢复。拉黑按固定渠道编号保存，报价、显示名或行情刷新不会解除；已下架渠道的记录也会保留，方便恢复。

名单保存在当前浏览器的 localStorage，不上传到 GitHub 或 CodeGo，也不跨设备同步。清除该网站存储会清除名单。相同站点的多个标签页会同步；浏览器禁止存储时明确提示仅当前页面生效。「恢复默认」仅重置评分条件，保留黑名单。

成功率来自 CodeGo 官方 `/api/group-status`。同时展示 所选模型最新成功率、渠道整体最新成功率，以及市场近 24h 成功率。界面注明采集时间、统计窗口和样本量；渠道窗口按该渠道子模型一致的窗口展示，不一致时标为未标注。

GitHub Pages 版：独立服务器每 10 分钟检查快照，过旧时触发 GitHub Actions 采集并发布；GitHub 自带定时保留为补充。Actions 执行和发布仍可能延迟，网页始终显示真实采集时间。网页每 60 秒检查同站新快照，不跨域访问源站，不含 Key，也不运行 Python 服务。手动「检查新快照」不触发新的采集。

如果行情时间一直不变，先看页面的「最近检查」：暂无新数据表示读取成功，但后台没有发布新快照；读取失败表示页面请求失败。快照过期时会显示采集任务入口，仓库维护者可在 Actions → Refresh data and deploy Pages → Run workflow 手动采集。服务器触发使用独立 systemd timer，不依赖 GitHub 的 schedule 事件；运维方法见 [服务器触发器](deploy/README.md)。

本地版：页面可见且自动刷新开启时每 60 秒刷新成功率，每 5 分钟刷新行情与模型列表。更新失败保留旧数据并提示，不将旧值冒充最新。页面关闭后停止本地刷新。

## GitHub Pages 部署

1. 将源码放入公开仓库，默认分支为 `main`。
2. 在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送到 `main` 或手动运行 **Refresh data and deploy Pages**。
4. 工作流先测试，再采集全部市场分页，生成 `dist/`，最后发布到项目路径 `/<仓库名>/`。

无需额外令牌或服务器。工作流采集失败会失败退出，保留上一版 Pages，不伪造更新时间。页面会提示过期。公开仓库长期无活动时 GitHub 可能暂停定时工作流，可在 Actions 中重新启用。

`build_pages.py` 只发布明确列出的网页资源和公开行情快照；本机服务、测试、配置和日志不会被打包到 Pages。数据通过部署产物更新，不产生每 10 分钟一次的数据提交。

## 打开

- 先执行 `python collect.py` 生成本地快照，再运行 `启动.ps1`，打开 http://127.0.0.1:8765 。需要 Python 3.10+，无需安装依赖。
- 也可以执行 `python server.py`，再打开上述地址。
- 直接打开 `index.html` 可以离线查看已保存快照；在线刷新需要本地服务。
- 页面点「刷新数据」重新抓取完整分页。刷新最短间隔 60 秒，失败保留上一份快照。

## 排名规则

默认：价格 20%、TTFT 35%、缓存 15%、缓存折算倍率 25%、历史实扣 5%。历史实扣最高 10%；支持均衡、速度优先、价格优先和手动调权。

所有基础条件匹配的渠道都打分并上榜。不可用、验证失败、平台观察中、当前模型故障、样本不足、成功率未达标、统计缺失及并发已满的渠道标为「观察」，不能进入调度建议。默认推荐门槛为 所选模型当前统计窗口至少 20 次请求、成功率至少 95%。这些是可调经验门槛，不是统计保证。

每个渠道显示缓存折算倍率 `倍率 / (缓存命中百分数 / 100)`，例如 0.2 / 80% = 0.25，越低越好。这是价格与缓存的综合比较指标，不代表实际账单倍率。零命中显示 ∞，缺失显示 —，该项均记 0 分。折算倍率分为 `100 × 0.20 / 缓存折算倍率`（上限 100），可独立调权，导出包含 `effectiveMultiplier`（零命中或缺失为 null）和 `cacheHitRate`。

价格分 `100 × 0.20 / 倍率`；TTFT 分 `100 / (1 + TTFT毫秒 / 10000)`；缓存分为接口百分比；历史实扣分 `100 × 入选最低实扣 / 本渠道实扣`。历史实扣缺失不给分，不当成免费。五项加权得到 0–100 的基础分 `baseScore`，保留在渠道详情中。

综合分采用固定分档：通过推荐门槛为 `50 + baseScore × 0.5`，范围 50–100；未通过为 `baseScore × 0.49`，范围 0–49。未达标的高性能渠道会明确降分，所有可推荐渠道都排在观察渠道之前，各档内保持基础分顺序。分档系数固定，不根据其他渠道最低分动态扣分；门槛或官方状态变化后重新计算。界面分数条、榜单、搜索名次和导出使用同一综合分，导出同时包含基础分和 `eligibility_bands_v1` 评分口径。分数是取舍指标，不是成功概率。

## 已核实的数据来源

- `GET /api/marketplace/groups?source=Codex%20Pro&model=gpt-6-astra&window_hours=24&page=1&page_size=20`：渠道倍率、验证结果、渠道 TTFT、历史实扣。服务端实际每页 20 条，采集器按响应的 total/page_size 遍历并检查完整性。
- `GET /api/group-status`：按 group_id 关联，再准确匹配所选模型 ID；取模型成功率、样本量、缓存。成功率窗口由 sample_window 指定，当前通常为 1 小时。
- `GET /api/pricing`：模型标准报价与分段计费表达式。界面用同一模型公开倍率比较价格，不计算混合用户的预计单次费用。
- `GET /api/status`：quota_per_unit，用于把历史扣费原始单位换成站内美元额度。
- `GET /api/marketplace/auto-route-pool`：匿名访问实测 401。网站前端用账户登录会话 Cookie 和 New-Api-User 请求它；普通模型 API Key 能否用于此管理接口未验证。本项目不需要此接口。

## 口径与接入边界

- TTFT 是渠道全模型近 24 小时统计，并非所选模型专属；不能拿模型连通性测试耗时冒充 TTFT。
- 缓存来自所选模型条目；接口未单独说明缓存窗口和分母。缓存高低也受用户工作负载影响。
- 历史实扣当前是该模型每百万实际 token 的平均扣费，非「平均每条请求」。它是输入、输出、缓存混合后的观察值，仅给低权重；站内美元额度不等于实际充值人民币支出。
- 不采用套餐倍率或个性化折扣；当前依据公开钱包倍率。公开并发仅作参考，不能代替实时限流。
- 「导出调度建议」生成最多 3 个真实 group_id 的优先级配置草案，未修改网站账户、绑定 Key 或发起付费测试。草案不是网站 PUT 接口的请求体。
- 推荐会话固定渠道，失败后冷却 60 秒，最多 2 次尝试；开始输出后不自动切换。这些是导出的策略建议，此版本没有执行代理。
- 本地行情超过 10 分钟或最新成功率超过 3 分钟时禁用导出；线上定时快照超过 20 分钟时禁用导出，并在导出中标记 `freshnessProfile: scheduled`。正式调度应接入自己的实时指标，并在切换前检查最新状态。

## 文件与验证

`collect.py` 负责公开数据采集和完整性检查；`rank.js` 是可复用评分器；`server.py` 提供仅绑定 127.0.0.1 的本地服务；`snapshot.json` 保存公开快照。

运行 `node test-rank.js`、`node test-blacklist.js` 和 `python -m unittest test_collect.py test_pages.py test_trigger.py` 检查筛选、黑名单、存储恢复、权重上限、过期保护、分页完整性、公开文件白名单及服务器触发器。运行 `python build_pages.py` 采集并构建静态站点。

采集器默认直连，避免继承失效的本机代理。如确需系统代理，可在启动前设置环境变量 `ROUTER_USE_PROXY=1`。
